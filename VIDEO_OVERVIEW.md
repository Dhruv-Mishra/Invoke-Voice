# Invoke Demo Video

## Format

Aim for 3-4 minutes at 1920x1080. Record the application, microphone, and system audio. Use a disposable repository and public research sources. Hide notifications from other apps, email addresses, access tokens, account identifiers, and private task history.

Opening line: **"This is Invoke. From Voice to Agency. Describe the work, and Invoke starts and follows the agent session for you."**

## Prepare

1. Install the release and complete local setup or configure an available hosted route. Test the exact microphone and speakers used for recording.
2. Sign in to Agency and check connections. Keep enterprise work-data access off for a public demo unless every visible source is approved for publication.
3. Register a small demo Git repository containing a basic webpage. Commit a clean baseline and select it as the default work area. Disable publishing permissions.
4. Clear the inbox and unrelated tasks. Turn off automatic idle hang-up for the recording, leave greetings on, and choose a readable theme.
5. Rehearse one task end to end. Check model availability, tool access, and the result before recording. Keep a separately recorded successful run available; do not substitute fabricated output.

## Recording Sequence

| Time | Show | Say / Do |
| --- | --- | --- |
| 0:00-0:20 | Invoke home and microphone dock | Deliver the opening line. Start a call, let the greeting finish, and briefly point out the active red hang-up control. |
| 0:20-0:40 | Voice and model route | "The conversation can use local models, hosted voice, or a mix. Delegated work uses the backend I choose." Show the actual configured route without exposing keys. |
| 0:40-1:25 | A real coding task | Say: "In the demo site, add a keyboard-accessible contrast toggle and remember the selection. Don't publish anything." Open Tasks and show the task running in its isolated worktree. |
| 1:25-1:55 | Queued follow-up | While the task is active: "For that task, after the toggle is ready, add a test for the saved preference and run it." Show the queued message and its eventual same-session execution. |
| 1:55-2:25 | Outcome and evidence | Let the concise completion announcement play. Open the task result, then show the actual changed app and test result. Do not treat dispatch as completion. |
| 2:25-2:55 | Research | Ask: "Find Microsoft's guidance on keyboard accessibility and summarize two checks for this page." Show public-source research and the answer. Mention that private work data requires explicit consent. |
| 2:55-3:20 | Voice-controlled UI | Say: "Switch to the Jarvis theme." Then: "Clear my notifications." Show the visible changes without interrupting the call. |
| 3:20-3:40 | Setup transparency and close | Briefly show Integrations or setup status: "When something needs installation, sign-in, or access, Invoke tells me what to do." End the call and show the GitHub release page. |

Closing line: **"Invoke turns a conversation into accountable work: one intent, a real agent session, and a result you can inspect."**

## Editing And Accuracy

- Trim waiting time only with a visible "Time compressed" label; do not imply edited timings are measured latency.
- Add concise captions for spoken requests and outcomes. Avoid a wall of architecture text.
- Show one authentic result clearly instead of rushing through many incomplete tasks.
- Show the selected route accurately. Do not call Agency research offline or claim enterprise permissions were verified by a catalog check.
- Record at normal playback speed when demonstrating speech latency. Hardware and provider availability affect results.
- Use original narration and no added copyrighted music. Existing theme-media provenance remains unverified.

## Optional 60-Second Cut

Invoke title and greeting (10s), spoken task and queue (20s), verified result (15s), theme/inbox command and GitHub release (15s). Label compressed waits.
