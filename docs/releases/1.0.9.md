# Invoke 1.0.9

## Opt-in Qwen3.6 35B-A3B Local Model

- Add **Settings > Keys and config > Local model**, which can switch local chat and voice from Gemma 4 E2B to [HauhauCS Qwen3.6-35B-A3B Uncensored Aggressive Q4_K_P](https://huggingface.co/HauhauCS/Qwen3.6-35B-A3B-Uncensored-HauhauCS-Aggressive). Gemma remains the default and stays installed.
- Selecting Qwen opens a confirmation that lists its cost: about 24 GB of RAM, about 47 GB of disk, and a slower first load. **Keep Gemma** restores the previous choice. Setup warns below 32 GB of system memory.
- Reuse a verified copy in `LocalVoiceStack/LLMs` or `QWEN_MODEL_PATH`, or download the SHA-256-pinned file.
- Add multi-token prediction: setup downloads only the 529 MB MTP layer from `unsloth/Qwen3.6-35B-A3B-MTP-GGUF` using a byte-range request, verifies it, and builds an accelerated copy. llama.cpp verifies every drafted token, so answers are unchanged.
- Launch Qwen with measured CPU settings: separate decode and batch thread counts, flash attention, no memory mapping (24.2 GB instead of 33.6 GB resident), an 8K context and a prompt-state cache. Qwen defaults to Regular routing.
- Add a short Qwen-only prompt for tool rounds about keeping user constraints, finishing multi-part requests, handling conditions, and asking when a target is unclear. Gemma and hosted prompts are unchanged.
- `npm run models -- qwen` performs the same verification and MTP build from the command line.

## Faster Local Voice For Every Model

- Stream local answers to speech as they decode instead of waiting for the full structured reply. Tool envelopes are never spoken.
- Checkpoint the shared prompt for Raw-scored routing so it is not reprocessed on every turn. This cut the prompt tokens reprocessed by 69% for Gemma and, with the thread change below, cut the Gemma Raw-scored median turn from 2.42 s to 0.98 s.
- Raise the default llama.cpp thread count to half the logical CPUs, capped at 16. On the reference workstation, Gemma prompt processing rose 62% and decode 35%.
- Prepare the model with Whisper's provisional transcript while the end of speech is being confirmed. This saves a small amount of prompt time; it can be turned off in Local performance.
- Add an opt-in pinned llama.cpp Vulkan runtime for partial GPU offload. On a 4 GB NVIDIA T400 it was slower than the CPU, so CPU remains the default.

## Validation And Limits

In the 54-case synthetic Jev workflow suite on a Threadripper PRO 5955WX, Regular routing results were:

- **Gemma:** passed 41 cases, as in 1.0.8, with the median turn falling from 5.72 s to 4.71 s.
- **Qwen with MTP:** passed 49 cases (90.7%) with a 2.72 s median turn.
- **Qwen without the Qwen-only prompt:** passed 47 cases, with identical results with and without MTP.

The median time from end of speech to first audio in the synthetic voice test fell from 5.34 s to 4.54 s for Gemma, and was 4.68 s for Qwen. See `UPGRADED_AGENT_REPORT.md` for methods, tables and caveats.

These are single-machine, synthetic measurements, not target-device guarantees; laptops with less memory bandwidth will decode Qwen more slowly. The Qwen weights are an uncensored fine-tune without refusal behavior. Invoke's consent gates, read-only scopes and tool validation still apply to every tool call. Installers remain unsigned. Physical audio, private enterprise search quality, and first-time setup on target devices were not independently validated.
